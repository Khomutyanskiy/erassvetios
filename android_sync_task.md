# eRassvet — синхронизация iOS → Android

Список изменений, внесённых в iOS-приложение за сегодняшнюю сессию, и задание на перенос в Android-проект. Оба приложения работают с одной и той же базой Firestore, поэтому часть пунктов (схема данных, правила безопасности) обязательна к переносу — иначе Android-клиент либо не увидит новые данные, либо будет писать в базу в старом формате.

---

## 1. Изменения схемы Firestore (обязательно для совместимости)

### 1.1. Коллекция `ads`

- Поле `status` теперь может принимать **4 значения** вместо двух:
  `active`, `inactive`, `pending` (на модерации), `rejected` (отклонено).
  Публичная лента по-прежнему должна фильтровать только `status == "active"`.
  В «Моих объявлениях» нужно уметь показывать и `pending`/`rejected` с понятными подписями.

- Новые поля: `adContactName` (String), `adContactValue` (String) — контакт, привязанный к конкретному объявлению.
  Если `adContactValue` не пустое — на странице объявления должен показываться **только** этот контакт (имя + значение), блок продавца и контакты профиля скрываются полностью.
  У старых объявлений (созданных до этого изменения) контакт может лежать внутри `contacts.other[]` с меткой `label == "Для этого объявления"` — при чтении такого объявления нужно достать его оттуда и показать так же, как новый формат (в iOS это сделано автоматически при декодировании).

### 1.2. Коллекция `chats`

- Новое поле `blockedBy: [String]` — массив uid участников, заблокировавших переписку.
  Если массив не пуст — чат должен быть доступен только для чтения с обеих сторон (поле ввода отключено, сверху баннер «Переписка ограничена»).

### 1.3. Новая коллекция `reports`

Создаётся при жалобе на собеседника в чате:
```
{
  chatId: string,
  reportedUid: string,
  reporterId: string,
  reason: string,
  createdAt: timestamp
}
```
Доступна на чтение только админам. Если в Android есть функционал «Пожаловаться» — писать сюда. Если нет — по крайней мере не блокироваться этой коллекцией.

### 1.4. Новая коллекция `app_config`, документ `moderation`

```
{ enabled: bool }
```
Если `enabled == true`, при публикации нового объявления нужно ставить `status = "pending"` вместо `"active"` (объявление не появится в ленте до одобрения админом). Если `enabled == false` — публикация как раньше, сразу `"active"`.

Это же поле нужно учитывать в лимите «не более 10 активных объявлений на пользователя», если он есть в Android: считать `status in [active, pending]`, а не только `active` — иначе лимит легко обойти.

## 2. Изменения правил безопасности Firestore (уже опубликованы, актуальны для обеих платформ)

- `support_contacts` — раньше запись была полностью запрещена (`allow write: if false`), теперь писать могут админы.
- `ads` — админам разрешено обновлять **только** поле `status` (нужно для модерации), обычное условие «продавец редактирует своё объявление» не изменилось.
- `app_config/{configId}` — читать может любой авторизованный пользователь, писать — только админ.
- `reports/{reportId}` — создавать может любой авторизованный пользователь (только от своего имени, `reporterId == auth.uid`), читать — только админ.
- **Важный фикс:** `ads/{adId}/viewers/{viewerId}` — раньше чтение было запрещено (`allow read: if false`), из-за чего счётчик просмотров **не работал вообще ни у кого** (код делал проверочное чтение перед инкрементом, получал ошибку доступа и тихо её проглатывал). Теперь `allow read, create: if true`, изменение/удаление по-прежнему запрещены.
  **Если в Android такая же логика подсчёта уникальных просмотров через подколлекцию `viewers` — обязательно проверить, не упирается ли она в ту же проблему.**

## 3. Логика подсчёта просмотров

- Идентификатор уникального просмотра (`viewerId`, он же id документа в `ads/{adId}/viewers/{viewerId}`) теперь берётся из **uid авторизованного аккаунта**, а не из анонимного идентификатора устройства. Для неавторизованных гостей — как раньше, анонимный id устройства.
  Причина: раньше при смене аккаунта на одном телефоне/симуляторе просмотр не засчитывался повторно, так как «зритель» определялся по устройству, а не по пользователю.
  **Рекомендация:** сделать так же в Android, иначе один и тот же человек, открывший объявление сначала в iOS-приложении, потом в Android, даст ровно один просмотр (что нормально) — но если Android продолжит считать по device-id, при смене аккаунта на одном Android-устройстве просмотр не засчитается второй раз, в отличие от iOS.

- Склонение слова «просмотр» должно быть грамматически верным: 1 просмотр / 2–4 просмотра / 5+ просмотров, и отдельно 11–14 всегда «просмотров». Проверить, что в Android это склонение реализовано (в iOS был баг — карточка объявления всегда писала «N просмотров», без склонения; список «Мои объявления» был в порядке).

## 4. Новый функционал (для полноты — реализовать в Android при необходимости)

1. **Модерация объявлений** — раздел в админ-панели: глобальный переключатель «Модерация включена/выключена» + очередь объявлений на модерации с кнопками «Одобрить»/«Отклонить». См. п. 1.1 и 1.4 по схеме данных.
2. **Жалобы и блокировка в чате** — кнопка «⋯» в шапке чата: «Пожаловаться» (с выбором причины: спам, мошенничество, оскорбления, другое) и «Заблокировать» / «Разблокировать» собеседника. См. п. 1.2 и 1.3.
3. **Удаление аккаунта с подтверждением** — экран с списком того, что будет удалено (профиль, объявления, избранное, чаты), полем пароля (повторная авторизация обязательна для Firebase Auth перед удалением аккаунта) и финальным подтверждением. При удалении аккаунта нужно почистить:
   - все объявления пользователя (`ads` где `sellerId == uid`) вместе с фото в Storage;
   - `users/{uid}/favorites/*`;
   - все чаты, где пользователь участник (`chats` где `uid in participants`);
   - аватар в Storage;
   - `user_public/{uid}`;
   - `users/{uid}`;
   - и только в конце — сам аккаунт Firebase Auth.
4. **Восстановление пароля по email** — ссылка «Забыли пароль?» на экране входа, отправка стандартного Firebase Auth email на сброс пароля (`sendPasswordReset`).
5. **Админка: управление контактами поддержки** (`support_contacts`) — добавление/редактирование/удаление/изменение порядка контактов, которые показываются пользователям на странице «Помощь». Актуально только если в Android есть свой админ-раздел.

## 5. Мелкие текстовые и визуальные правки (低 приоритет, но для единообразия)

- Текст после публикации объявления должен ссылаться на **«Ленту»**, а не «главную страницу» — если в Android похожая формулировка, поправить аналогично.
- На карточке объявления и в фильтре бейдж типа сделки (Предлагаю / Требуется / Даром) теперь показывается **всегда** (раньше — только для «Требуется»/«Даром»), с отдельным цветом на каждый тип:
  - Предлагаю — синий `#3D7DFF`
  - Требуется — оранжевый `#F0956B`
  - Даром — зелёный `#3FBF7F`
- Если у объявления нет ни одного фото, блок-заглушка «Фото пока недоступно» теперь вообще не показывается (раньше показывался всегда, если фото нет). Заглушка используется только когда фото есть, но не загрузилось (битая ссылка/нет сети).
- При нажатии на контакт (телефон/email/ссылка), если система не может открыть приложение (типично для симулятора/эмулятора), значение теперь копируется в буфер обмена с уведомлением «Скопировано» — чтобы нажатие не выглядело нерабочим.

## Приоритеты для Android

1. **Критично** (иначе баги «не совпадают данные между платформами»): п. 1 и 2 целиком — иначе Android либо не увидит новые поля/статусы, либо будет писать в устаревшем формате.
2. **Важно**: п. 3 (просмотры) — если Android уже считает просмотры и упирается в такую же проблему с правилами чтения `viewers`.
3. **По усмотрению/бэклог**: п. 4 (новый функционал) и п. 5 (текстовые/визуальные правки) — можно переносить по одному, не блокируют совместимость данных.
